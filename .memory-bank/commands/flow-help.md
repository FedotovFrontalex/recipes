# Команда: flow-help — карта фреймворка и маршрутизация

> Канон команды. Вызывается через `/flow-help [вопрос]`.
> Ответь на вопрос пользователя о работе фреймворка, опираясь на карту ниже.

---

## Маршрутизация задач

| Ситуация | Что делать |
|---|---|
| Мелкий косяк, ~до 30 минут | Без протокола: прогретый контекст → анализ → фикс → проверки из gates.md → коммит |
| Доработка до ~2 часов | `/flow-mini "имя"` — протокол на main |
| Фича/рефакторинг > 2 часов | `/flow-new "имя"` — полный протокол: worktree + ветка + Draft PR |
| Большая фича (1–2+ дня) | Сначала `spec.md` (шаблон `.flow/templates/spec.md`) в рамках `/flow-new`, затем шаги |
| Прерванная работа | `/flow-resume NNNN` |
| Всё готово, нужно влить | `/flow-review NNNN` |
| Обсуждение/дизайн (без кода) | Без протокола: прайминг по `.memory-bank/index.md` → обсуждение; итоги — в протокол при старте |

## Карта фреймворка

- `.memory-bank/` — база знаний: `index.md` (прайминг сессии), `docs/` (C4: L1/L2/L3),
  `mbb/` (правила ведения), `learnings/` (уроки), `commands/` (канон команд + шаблоны протокола).
- `.protocols/NNNN-имя/` — единица работы: `plan.md` (ADR + контракт), `YY-шаг.md`,
  `log.md` (append-only), `context.md` (текущее состояние), `review-plan.md`/`review-log.md` (на ревью).
- `.flow/gates.md` — команды проверок (typecheck/lint/test/build), обязательны после каждого шага.
- `.flow/templates/spec.md` — шаблон спецификации больших фич.
- `.zcode/commands/` — адаптеры слэш-команд ZCode → канон.
- `AGENTS.md` — правила поведения агента в этом проекте.

## Жизненный цикл протокола

```
обсуждение → /flow-new → [шаг 00: план+PR] → шаг 01..NN (проверки после каждого)
           → (по необходимости /flow-resume) → /flow-review (гейты, merge, чистка,
             знания в memory-bank и learnings) → готово
```

## Параллельная работа

Пока один протокол в реализации, можно параллельно обсуждать следующий и вести второй
протокол: у каждого свой worktree, своя ветка, свой PR. Merge-очередь разруливается
на шаге 4-m `/flow-review`.
