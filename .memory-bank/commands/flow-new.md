# Команда: flow-new — зафиксировать план в протокол

> Канон команды. Вызывается через `/flow-new "краткое имя задачи"`.
> Контекст: план доработки уже обсуждён с пользователем в этой или предыдущей сессии.
> Твоя задача — финализировать план и создать изолированное рабочее пространство.

**Действуй строго по алгоритму.** В шаблонах инструкции в `{фигурных скобках}` — для тебя.
Шаблоны файлов лежат в `.memory-bank/commands/templates/` — читай их при генерации.

---

## Фаза 0: Подготовка контекста

1. Прочитай `.memory-bank/index.md` и файлы, релевантные теме доработки.
2. Прочитай `.flow/gates.md` (команды проверок). Если в нём остались `TODO` — определи
   команды проверок по проекту (package.json scripts, Makefile, pyproject и т.п.),
   заполни gates.md и покажи пользователю результат. Не продолжай с пустыми гейтами.
3. Если это большая фича (оценка > 1–2 дней) — сначала зафиксируй спецификацию по
   шаблону `.flow/templates/spec.md` в отдельном протоколе-документе (см. Фазу 3).

## Фаза 1: Проверка окружения

1. Убедись, что текущая ветка — `main`, рабочая директория чиста. Если есть незакоммиченные
   изменения — спроси пользователя, как поступить (commit / stash / игнорировать).
2. `git fetch origin`; сверь локальный `main` с `origin/main`. Если отстаёт — остановись
   и предложи обновить. (Если репозиторий без remote — пропусти шаг.)
3. Прогони базовые проверки из `gates.md` (typecheck, lint). Если падают — предложи
   сначала починить; стартовать протокол на красной базе нельзя.
4. Если `git` недоступен — остановись с объяснением: протоколы требуют Git.

## Фаза 2: Номер и рабочее пространство

1. Определи номер нового протокола NNNN: посмотри `.protocols/` и папку worktrees
   (`../worktrees/`); возьми максимальный существующий номер + 1.
2. Создай ветку и worktree:
   ```
   git worktree add --checkout -b NNNN-<краткое-имя> ../worktrees/NNNN-<краткое-имя> main
   ```
   (если `../worktrees/` создать нельзя — используй `<project>/.worktrees/` и предупреди).
3. **С этого момента твой рабочий корень (CWD) — папка worktree.** Все дальнейшие команды —
   из неё. Запомни и запиши в артефакты абсолютные пути: `PROJECT_ROOT` и `CWD`.

## Фаза 3: Артефакты протокола

1. В worktree создай папку `.protocols/NNNN-<краткое-имя>/`. Проверь, что номер свободен.
2. Создай файлы по шаблонам из `templates/`:
   - `plan.md` — ADR-резюме + High-Level Plan (контракт) + Workflow-цикл + принципы;
   - `00-setup.md` — технический первый шаг;
   - `01-<имя-шага>.md`, `02-...` — по одному файлу на каждый шаг плана;
   - `context.md` — состояние: Current Step, Status, Next Action, пути;
   - `log.md` — append-only журнал;
   - (опционально) `spec.md` — спецификация по шаблону `.flow/templates/spec.md` для больших фич.
3. Принципы плана (обязательны):
   - **Баланс и простота**: самые простые из возможных решения; никаких лишних абстракций и оверинжиниринга.
   - **Никакого легаси**: устаревший код удаляется; обратная совместимость не требуется.
   - **Качественные тесты**: каждый шаг, добавляющий поведение, описывает, какие тесты и что именно проверяют (Red → Green → Refactor).
   - **MBB**: шаги, меняющие документацию, обновляют Memory Bank по правилам `.memory-bank/mbb/principles.md`.
   - **Детализация**: план самодостаточен — выполняется без доступа к текущему диалогу; в каждом шаге Briefing (цель, ключевые файлы, тонкости) и Sub-tasks (до 5–7 задач).
   - **Размер шагов**: шаг = итерация, которая уверенно помещается в один контекст; крупное — дроби.
4. Заполни `context.md`: Current Step = 1, Status = In Progress, Next Action = «Шаг 1 (см. 01-<имя>.md)».

## Фаза 4: Публикация

1. Первый коммит: `git add .protocols/NNNN-<краткое-имя>` →
   сообщение `feat(protocol): add plan for NNNN-<имя> [protocol-NNNN/00]`.
2. `git push --set-upstream origin NNNN-<краткое-имя>`.
3. Если доступен `gh` — создай Draft PR:
   `gh pr create --draft --title "WIP: NNNN — <имя>" --body "Работа по протоколу NNNN. План: .protocols/NNNN-<имя>/"`
   и сообщи URL. Если `gh` недоступен — пропусти PR и скажи об этом.

## Фаза 5: Отчёт

Выведи пользователю:
- содержимое `plan.md` (и `spec.md`, если есть) на согласование;
- пути: worktree, папка протокола; номер PR или его отсутствие;
- что дальше: правки плана (если есть) фиксируются amend-коммитом; затем — работа по шагам
  («продолжай работу по плану протокола» или `/flow-resume NNNN` в новой сессии).

**Не переходи к выполнению Шага 1, пока пользователь не утвердил план.**
