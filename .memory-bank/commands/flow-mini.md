# Команда: flow-mini — быстрый протокол на main

> Канон команды. Вызывается через `/flow-mini "краткое имя задачи"`.
> Для доработок до ~2 часов: план + проверяемые шаги, но без worktree и PR —
> всё ведётся в ветке `main`. Когда больше по объёму — переходи на `/flow-new`.

---

## Фаза 1: Проверка окружения

1. Текущая ветка — `main`, директория чиста (незакоммиченное — спроси пользователя).
2. `git fetch origin`, сверь с `origin/main` (без remote — пропусти).
3. Прочитай `.flow/gates.md`; если есть TODO — заполни по проекту, как в `flow-new.md`.

## Фаза 2: Артефакты

1. Определи номер NNNN (max в `.protocols/` и worktrees + 1). Проверь уникальность.
2. Создай `.protocols/NNNN-<краткое-имя>/` с файлами по шаблонам из `templates/`:
   - `plan.md` — по шаблону `protocol-plan.md` (раздел Plan — плоский список шагов с задачами,
     без отдельных файлов шагов);
   - `context.md`, `log.md`.
3. Принципы — те же, что в `flow-new.md` (простота, никакого легаси, тесты, MBB, самодостаточность).
4. Коммит: `feat(protocol): add plan for NNNN-<имя> [protocol-NNNN/00]`, пуш (если есть remote).

## Фаза 3: Выполнение (Workflow-цикл для каждого шага)

- **Перед шагом:** прочитай `context.md` → текущий шаг; убедись, что ты в `main` и всё закоммичено.
- **Во время:** выполняй задачи шага. **Файлы плана — контракт, не менять.**
- **После шага:**
  1. Прогони проверки из `.flow/gates.md` (typecheck, lint, релевантные тесты) — до зелёного.
  2. Запись в `log.md`: что сделано и почему (неочевидные решения), ID коммита.
  3. Полностью перепиши `context.md` под следующий шаг.
  4. Коммит `type(scope): subject [protocol-NNNN/YY]`, пуш.
  5. Отчёт пользователю (формат ниже).

## Формат отчёта о шаге

```
#### Шаг {YY} протокола {NNNN}
**Сделано:** что, где, для чего (дублируется в log.md)
**Проверки:** какие гонялись (typecheck/lint/test), результат
**Git:** ветка, коммит (hash, сообщение), пуш; main чиста
**Статус протокола:** шаг X из N; что дальше
```

## Завершение

Когда все шаги выполнены: финальный отчёт, при желании пользователя — быстрый самостоятельный
`git diff`-ревью; уроки (если появились) — в `learnings/`, затронутые документы Memory Bank —
актуализировать. Worktree и merge-фаза не нужны: работа уже в main.
