# Шаблон: review-plan.md (план ревью и merge)

> Создаётся командой flow-review в папке протокола. Это чек-лист ревьюера.

```markdown
# Review and Merge Plan: NNNN — {краткое имя}

## Пути
- Project root (CWD ревьюера): {абсолютный путь}
- Worktree (код): {абсолютный путь}
- Папка протокола: {абсолютный путь}
- PR: {URL/номер/нет}

## Принципы ревью (MUST follow)
- Методичность: строго по шагам, без пропусков.
- Контроль окружения: pwd и git branch --show-current — перед и после каждого шага.
- Отчётность: каждое действие и результат — в review-log.md (append-only).

## Detailed Plan

### Шаг 1-m. CI (если есть)
- `gh pr checks <PR>`; провалы = блокер. Нет gh — пропустить.

### Шаг 2-m. Локальная верификация (код worktree, запуск из project root)
- Все проверки из .flow/gates.md + build (полная сборка).
- Ошибки → исправления в ветке протокола, тег [protocol-NNNN/2m-fix].

### Шаг 3-m. Ревью полноты и качества
- План vs факт: каждое требование plan.md реализовано; log.md согласован с диффом.
- git diff main...NNNN: стандарты кода, тесты на новое поведение, MBB-документация.
- Сканирование диффа: TODO/FIXME/HACK, заглушки, случайные файлы, секреты.
- (опционально) независимое ревью субагентом.
- Критичное → исправить; некритичное → согласовать (сейчас / техдолг / новый протокол).

### Шаг 4-m. Merge (только после явного «да» пользователя)
- git checkout main && git pull origin main
- git merge --no-ff NNNN-<имя> && git push origin main
- Конфликты → стоп, план разрешения; ориентир — последние закрытые протоколы.

### Шаг 5-m. Чистка
- Удалить: remote-ветку, локальную ветку, worktree.
- Папка протокола остаётся на main как история.

### Шаг 6-m. Знания
- Обновить затронутые документы .memory-bank/docs/ (MBB, SSOT).
- Уроки → learnings/anti-patterns.md и learnings/performance-patterns.md (источник, confidence).
- Коммит: docs(memory-bank): update after protocol NNNN [protocol-NNNN/6m].
```
