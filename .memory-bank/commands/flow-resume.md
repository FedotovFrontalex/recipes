# Команда: flow-resume — восстановить работу по протоколу

> Канон команды. Вызывается через `/flow-resume NNNN`.
> Ты — агент, продолжающий прерванную работу. Задача — безопасно восстановить контекст
> и подготовиться к следующему шагу. Главный принцип: «не доверяй, а проверяй» —
> официальное состояние (`context.md`) сверяется с зафиксированным (git) и текущим (файлы).

**Входные данные:** номер протокола = `$1` (передан вызывающей командой; если пуст —
попроси пользователя назвать номер или выбери незавершённый протокол из `.protocols/`).

---

## Фаза 1: Локализация и сбор данных

1. Найди рабочую среду: определи полное имя `NNNN-<имя>` по содержимому `../worktrees/`
   (или `<project>/.worktrees/`). **Перейди в эту папку — это твой рабочий корень (CWD).**
2. Прочитай «официальный» статус: `.protocols/NNNN-<имя>/context.md` → запомни `Current Step`.
3. Проверь «зафиксированный» статус: `git log -1 --pretty=format:"%s"` → найди тег
   `[protocol-NNNN/XX]` в последнем коммите.
4. Проверь «текущее» состояние: `git status --porcelain` → есть ли незакоммиченные изменения.
5. Проверь чистоту `main`: файлы из ветки протокола не должны попасть в основной репозиторий.

## Фаза 2: Диагностика (три сценария)

**A. Чистое состояние (частый случай):** `git status` пуст, номер последнего коммита = `Current Step - 1`.
→ Работа прервана между шагами. Готов к Фазе 3.

**B. Прерывание в середине шага:** `git status` показывает изменения.
→ Сообщи: «Обнаружены незавершённые изменения для шага [Current Step]». Изучи изменённые
файлы, определи, что сделано и что нет, продолжай выполнение шага с места прерывания.

**C. Сбой после коммита, до обновления протокола:** `git status` пуст, но номер коммита = `Current Step`.
→ Самокоррекция: дополни `log.md` записью о шаге (из сообщения коммита), перепиши `context.md`
(Current Step + 1, новый Next Action). Дальше — как в сценарии A.

## Фаза 3: Подготовка к работе

1. Отметь восстановление: посчитай записи `Restore context` в `log.md` и добавь после
   заголовка запись `Restore context: protocol-NNNN#ctx-<N+1>`.
2. Прочитай `context.md` → `Current Step` и `Next Action` → открой файл текущего шага
   (`YY-<имя>.md`) и изучи его полностью — это единственный источник для следующего шага.
3. Проверь окружение: CWD — корень worktree; ветка Git — `NNNN-<имя>`; базовые проверки
   (typecheck/lint из `.flow/gates.md`) проходят.

## Фаза 4: Отчёт о готовности

> Пример (сценарий B):
> «Контекст восстановлен для протокола `0042-auth`. Обнаружены незавершённые изменения
> шага `03`, изучил их, готов продолжить с места прерывания.
> **CWD:** {абсолютный путь} · **Ветка:** 0042-auth · **main:** чистая
> **Текущее состояние:** шаг 03 · **Следующая задача:** {кратко}»

**Жди подтверждения пользователя, прежде чем продолжать выполнение.**
Далее работа идёт по Workflow-циклу из `plan.md` протокола.
