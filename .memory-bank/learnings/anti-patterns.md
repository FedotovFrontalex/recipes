# ❌ Anti-patterns (уроки проекта)

> Наполняется на шаге 6-m команды `/flow-review` после каждого merge и вручную по мере находок.
> Агент проверяет этот список перед проектированием решения; записи с confidence ≥ 0.85
> обязательно выносятся предупреждением в план протокола.

Формат записи:

```markdown
### [NP-NN] Краткое название анти-паттерна
- **Контекст:** где/когда проявилось
- **Анти-паттерн:** что было сделано и почему плохо
- **Как правильно:** что делать вместо этого
- **Источник:** протокол NNNN, коммит abc1234
- **Confidence:** 0.0–1.0 (насколько правило подтверждено)
- **Статус:** candidate → proven
```

### [NP-01] Пример-шаблон (замените реальными записями)
- **Контекст:** пример
- **Анти-паттерн:** пример
- **Как правильно:** пример
- **Источник:** —
- **Confidence:** 0.0
- **Статус:** candidate

### [NP-02] Наивный split по запятой для CSV
- **Контекст:** парсинг receps.csv (названия рецептов содержат запятые)
- **Анти-паттерн:** `line.split(',')` ломает записи вида `"Пирог с курицей, сыром",
  Пироги и выпечка,https://...` — поля «съезжают», категории превращаются в мусор
- **Как правильно:** парсер RFC4180 с поддержкой кавычек (см. scripts/lib/csv.mjs)
  + валидатор, который ловит «мусорные» категории и пустые поля
- **Источник:** протокол 0001, шаг 01
- **Confidence:** 0.95
- **Статус:** proven

### [NP-03] Абсолютные пути в статике для GitHub Pages
- **Контекст:** сайт деплоится в подпут `/recipes/` (project pages), а не в корень домена
- **Анти-паттерн:** ссылки вида `/css/styles.css` или `fetch('/data/...')` дают 404
  на GitHub Pages project site
- **Как правильно:** только относительные пути (`./css/...`, `./data/...`);
  проверять grep'ом на ведущий слэш перед коммитом (см. шаг 04 протокола 0001)
- **Источник:** протокол 0001, шаг 04
- **Confidence:** 0.95
- **Статус:** proven
