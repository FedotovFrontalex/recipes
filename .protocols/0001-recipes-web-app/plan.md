# 0001 — Веб-приложение рецептов (GitHub Pages)

## ADR-style Summary

- **Context:** Есть `receps.csv` (~290 рецептов: название, категория, ссылка на
  ivlevchefbooks.ru). Нужен удобный просмотр в вебе: навигация по категориям, поиск,
  комфорт и на desktop, и на телефоне. Деплой — GitHub Pages
  (`git@github.com:FedotovFrontalex/recipes.git`, SSH).
- **Problem Statement:** CSV неудобен для повседневного пользования: нет поиска,
  фильтров, мобильного вида и публичного URL.
- **Decision:** Статическое SPA **без сборки и без зависимостей** (vanilla JS + CSS)
  в корне репозитория. Данные генерируются из `receps.csv` в `data/recipes.json`
  node-скриптом. Деплой — GitHub Actions (`actions/deploy-pages`) при push в `main`.
- **Alternatives:**
  - Vite + React — сборка и зависимости не нужны справочнику из ~290 ссылок; отклонено.
  - Ветка `gh-pages` — Actions декларативнее и воспроизводимее; отклонено.
  - SSG/серверный рендеринг — оверкилл для задачи; отклонено.
- **Consequences:** ноль зависимостей и нулевая сборка; обновление данных — одна
  команда `npm run build:data`; поиск/фильтрация клиентские (на 290 записях —
  мгновенно). Жертвуем: при росте до многих тысяч записей понадобится пагинация
  или индексация.

## Protocol Workflow (инструкция по выполнению — одинакова для всех шагов)

**Пути:**
- PROJECT_ROOT: `C:\Users\Алексей\Desktop\coocking`
- CWD (worktree): `C:\Users\Алексей\Desktop\coocking\.worktrees\0001-recipes-web-app`
- Папка протокола: `C:\Users\Алексей\Desktop\coocking\.worktrees\0001-recipes-web-app\.protocols\0001-recipes-web-app`

**Вся работа ведётся из CWD (worktree).**

### A. Перед началом шага
1. Прочитай `context.md` → `Current Step` и `Next Action`.
2. Открой и изучи файл текущего шага (`YY-<имя>.md`) — единственный источник инструкций.
3. Убедись, что все предыдущие изменения закоммичены, а ветка main чиста (наши файлы не попали туда).

### B. Во время шага
1. Выполняй Sub-tasks файла шага последовательно.
2. Не изменяй файлы плана (`plan.md`, `YY-*.md`) — они контракт.
3. Следуй Generic Principles ниже.

### C. После завершения шага
1. Прогони проверки из `.flow/gates.md` (typecheck, тесты) — до зелёного результата.
2. Добавь запись в `log.md`: что сделано и почему (неочевидные решения), ID коммита.
3. Полностью перепиши `context.md` под следующий шаг (Current Step + 1, новый Next Action).
4. Коммит `type(scope): subject [protocol-0001/YY]`; пуш — как только SSH заработает (локальный коммит обязателен всегда).
5. Отчёт пользователю:

    **Сделано:** что, где, для чего (дублируется в log.md)
    **Проверки:** какие гонялись, что прошло/нет и почему
    **Git:** ветка, коммит (hash, сообщение), пуш; main чиста
    **Рабочая папка:** абсолютный путь CWD
    **Статус протокола:** шаг X из N; что дальше

## Generic Principles (MUST follow)

- **Баланс и простота:** самые простые работающие решения; без оверинжиниринга и лишних абстракций.
- **Никакого легаси:** устаревшее удаляется; обратная совместимость не требуется.
- **Стандарты кодирования:** JSDoc на функциях, консистентный стиль, без зависимостей.
- **MBB:** документация обновляется по правилам `.memory-bank/mbb/` (SSOT, duo-файлы, C4).
- **Качественные тесты:** каждый шаг с поведением — с проверками; для данных — валидатор, для UI — ручные сценарии.
- **Проверка main:** перед каждым коммитом убеждайся, что изменения не утекли в основной репозиторий.
